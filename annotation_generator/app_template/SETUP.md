# Annotation Tool — Self-Hosting Guide

Deploy your own instance of the Annotation Tool with your own database. This guide covers four platforms: **Render**, **Railway**, **Fly.io**, and **Heroku**.

---

## Prerequisites

- A GitHub (or GitLab) account with a fork/copy of this repository
- A free account on your chosen hosting platform

## Environment Variables

| Variable | Required | Description |
|----------|----------|-------------|
| `DATABASE_URL` | **Yes** | PostgreSQL connection string (e.g. `postgresql://user:pass@host:5432/dbname`) |
| `SECRET_KEY` | Recommended | Random string for session signing. Auto-generated on some platforms. |
| `DB_SCHEMA` | Optional | PostgreSQL schema name for table isolation (useful if sharing a DB server) |

> **Important:** Without `DATABASE_URL` set, the app falls back to a local SQLite file which **will lose all data on redeploy**. Always use PostgreSQL in production.

## Option 1: Render (Easiest)

Render auto-provisions a PostgreSQL database from the included `render.yaml`.

### Steps

1. **Fork this repo** to your GitHub account.

2. **Create a Render account** at [render.com](https://render.com) and connect your GitHub.

3. **New Blueprint Instance:**
   - Go to the Render dashboard → **New** → **Blueprint**
   - Select your forked repo
   - Render reads `render.yaml` and creates both the web service and PostgreSQL database automatically

4. **Wait for deploy** — Render will build, provision the DB, and set `DATABASE_URL` for you.

5. **Visit your app** at the URL Render assigns (e.g. `https://annotation-tool-xxxx.onrender.com`).

### Manual Setup (without Blueprint)

1. **Create a PostgreSQL database:**
   - Dashboard → **New** → **PostgreSQL**
   - Name: `annotation-db`, Plan: Free
   - Copy the **Internal Database URL**

2. **Create a Web Service:**
   - Dashboard → **New** → **Web Service**
   - Connect your repo, set:
     - **Build Command:** `pip install -r requirements.txt`
     - **Start Command:** `gunicorn app:app --bind 0.0.0.0:$PORT`
   - Add environment variables:
     - `DATABASE_URL` = (paste the Internal Database URL)
     - `SECRET_KEY` = (any random string)

3. Deploy.

## Option 2: Railway

### Steps

1. **Create a Railway account** at [railway.app](https://railway.app).

2. **New Project → Deploy from GitHub Repo** — select your fork.

3. **Add a PostgreSQL plugin:**
   - In your project, click **New** → **Database** → **PostgreSQL**
   - Railway auto-injects `DATABASE_URL` into your service

4. **Configure the service:**
   - Set the start command: `gunicorn app:app --bind 0.0.0.0:$PORT`
   - Add variable: `SECRET_KEY` = (any random string)

5. **Deploy** — Railway builds and deploys automatically.

6. **Generate a domain:**
   - Service → **Settings** → **Networking** → **Generate Domain**

### Database Connection String

Railway sets `DATABASE_URL` automatically when you link the PostgreSQL plugin. No manual copying needed.

## Option 3: Fly.io

### Steps

1. **Install the Fly CLI:**
   ```bash
   curl -L https://fly.io/install.sh | sh
   fly auth login
   ```

2. **Launch the app** from the `app_template` directory:
   ```bash
   cd annotation_generator/app_template
   fly launch
   ```
   - Choose a name, region, and say **No** to the default database for now.

3. **Create a PostgreSQL cluster:**
   ```bash
   fly postgres create --name annotation-db
   ```

4. **Attach the database to your app:**
   ```bash
   fly postgres attach annotation-db
   ```
   This automatically sets `DATABASE_URL` as a secret.

5. **Set the secret key:**
   ```bash
   fly secrets set SECRET_KEY=$(openssl rand -hex 32)
   ```

6. **Create a `Dockerfile`** (if not present):
   ```dockerfile
   FROM python:3.11-slim
   WORKDIR /app
   COPY requirements.txt .
   RUN pip install --no-cache-dir -r requirements.txt
   COPY . .
   CMD ["gunicorn", "app:app", "--bind", "0.0.0.0:8080"]
   ```

7. **Create `fly.toml`** (if not generated by `fly launch`):
   ```toml
   app = "your-app-name"

   [build]

   [http_service]
     internal_port = 8080
     force_https = true

   [[services]]
     internal_port = 8080
     protocol = "tcp"

     [[services.ports]]
       port = 80
       handlers = ["http"]

     [[services.ports]]
       port = 443
       handlers = ["tls", "http"]
   ```

8. **Deploy:**
   ```bash
   fly deploy
   ```

## Option 4: Heroku

### Steps

1. **Install the Heroku CLI:**
   ```bash
   # macOS
   brew tap heroku/brew && brew install heroku
   # Or see https://devcenter.heroku.com/articles/heroku-cli
   ```

2. **Create a Heroku app:**
   ```bash
   cd annotation_generator/app_template
   heroku create your-app-name
   ```

3. **Add a PostgreSQL addon:**
   ```bash
   heroku addons:create heroku-postgresql:essential-0
   ```
   This automatically sets `DATABASE_URL`.

4. **Set the secret key:**
   ```bash
   heroku config:set SECRET_KEY=$(openssl rand -hex 32)
   ```

5. **Create a `Procfile`** (if not present):
   ```
   web: gunicorn app:app --bind 0.0.0.0:$PORT
   ```

6. **Deploy:**
   ```bash
   git push heroku main
   ```

## Verifying Your Setup

After deploying, visit your app URL. If everything is configured correctly:

- You'll see the landing page with "Get Started" and "Login" buttons
- You can register, create projects, and upload CSVs
- Data persists across redeploys

If `DATABASE_URL` is not set, you'll see a **yellow warning banner** on the landing page indicating that SQLite is in use and data may be lost on redeploy. Follow the instructions on the `/setup` page to fix this.

## Using a Separate / Existing PostgreSQL Database

If you already have a PostgreSQL server (e.g. AWS RDS, Supabase, Neon, or self-hosted):

1. Create a database:
   ```sql
   CREATE DATABASE annotation_tool;
   ```

2. Set the connection string as `DATABASE_URL`:
   ```
   postgresql://username:password@hostname:5432/annotation_tool
   ```

3. (Optional) Use `DB_SCHEMA` to isolate tables:
   ```
   DB_SCHEMA=my_team_schema
   ```

The app auto-creates all tables on first startup.

## Troubleshooting

| Issue | Fix |
|-------|-----|
| `DATABASE_URL` not set | Check your platform's env var / secrets config |
| `postgres://` in URL | The app auto-converts to `postgresql://` — no action needed |
| Tables not created | The app runs `db.create_all()` on startup automatically |
| Data lost on redeploy | You're using SQLite — set `DATABASE_URL` to a PostgreSQL instance |
| Connection refused | Check that your DB allows connections from your app's IP/network |
