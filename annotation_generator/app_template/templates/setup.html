Deploy on Render Easiest

Render auto-provisions a database from the included render.yaml.

  1. 1
    Fork this repo to your GitHub account.
  2. 2
    Create a Render account at render.com and connect GitHub.
  3. 3
    New Blueprint: Dashboard → New → Blueprint → select your repo.
    Render reads render.yaml and creates the web service + PostgreSQL database automatically.
  4. 4
    Wait for deploy — DATABASE_URL is set automatically. You're done.
Deploy on Railway
  1. 1
    Create a project at railway.app → Deploy from GitHub Repo.
  2. 2
    Add PostgreSQL: In your project, click New → Database → PostgreSQL.
    Railway auto-injects DATABASE_URL.
  3. 3
    Set start command: 
    gunicorn app:app --bind 0.0.0.0:$PORT
  4. 4
    Add secret key: Variables → SECRET_KEY = any random string.
  5. 5
    Generate a domain: Settings → Networking → Generate Domain.
Deploy on Fly.io
  1. 1
    Install the Fly CLI and log in: 
    curl -L https://fly.io/install.sh | sh
fly auth login
  2. 2
    Launch the app: 
    cd annotation_generator/app_template
fly launch
  3. 3
    Create and attach PostgreSQL: 
    fly postgres create --name annotation-db
fly postgres attach annotation-db
    This sets DATABASE_URL automatically.
  4. 4
    Set secret key and deploy: 
    fly secrets set SECRET_KEY=$(openssl rand -hex 32)
fly deploy
Deploy on Heroku
  1. 1
    Install the Heroku CLI and create an app: 
    heroku create your-app-name
  2. 2
    Add PostgreSQL: 
    heroku addons:create heroku-postgresql:essential-0
    This sets DATABASE_URL automatically.
  3. 3
    Set secret key: 
    heroku config:set SECRET_KEY=$(openssl rand -hex 32)
  4. 4
    Create a Procfile: 
    web: gunicorn app:app --bind 0.0.0.0:$PORT
  5. 5
    Deploy: 
    git push heroku main
Use Your Own PostgreSQL

If you already have a PostgreSQL server (AWS RDS, Supabase, Neon, self-hosted, etc.):

  1. 1
    Create a database: 
    CREATE DATABASE annotation_tool;
  2. 2
    Set DATABASE_URL as an environment variable on your hosting platform: 
    postgresql://username:password@hostname:5432/annotation_tool
  3. 3
    (Optional) Set DB_SCHEMA to isolate tables if sharing a DB server: 
    DB_SCHEMA=my_team_schema

Tables are created automatically on first startup. No migrations needed.
